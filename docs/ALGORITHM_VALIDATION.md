# 알고리즘 적용 검증 결과

2026-10-15, Windows / JDK 21 / Gradle 8.14.3 / Spring Boot 3.5.7 / H2 2.3.232 / Node.js 24.

## 자동 검증

- 백엔드 **27개 테스트, 실패 0**: 회원/API 9개, 추천 API 4개, Jaccard/LCS 계산 3개, 비밀번호 인코더 3개, 검색 정규화/집합 연산 2개, 검색 API/일관성 6개.
- 프론트엔드 **22개 파일, 144개 테스트 통과**.
- Vue 프로덕션 빌드, 변경한 Vue 화면·서비스·테스트 ESLint 통과.
- Gradle `bootJar` 성공.

LCS는 별도 부분수열 완전 탐색 구현과 난수 500쌍을 대조했다. 검색은 NFKC·부분 포함·AND/OR·중복 점수·필터·전체 건수·페이지·CRUD·롤백·초기 재구축을 검증했다. 동시 수정 테스트에서 H2 REPEATABLE_READ의 버전 혼합을 발견해 검색/추천을 SERIALIZABLE로 변경했고 같은 테스트가 통과했다.

테스트는 외부 API 키가 없는 임시 영문 경로와 H2 메모리 DB에서 실행했다. 사용자 DB, 회원, 키 파일을 테스트에 사용하지 않았다.

## 실제 HTTP 및 파일 DB

별도 18081 포트와 임시 H2 파일로 다음을 검증했다.

1. 기존 샘플 게시글의 최초 검색 인덱스 구축 및 검색.
2. 신규 Argon2id 회원 가입/로그인.
3. 공통 장소가 있는 코스 3개 등록 및 포함 검색 AND 결과.
4. 기준 `A B C D`에 역순 `D C B A`와 부분 일치 `A B E D`의 추천 순위.
5. 게시글 수정 직후 검색 인덱스와 추천 후보 갱신.
6. 서버 종료 및 동일 파일 DB로 재시작.
7. 부분 검색 결과·추천 순위 유지, 저장된 회원의 재로그인.
8. 탈퇴 후 작성글·검색 posting 제거.

검증용 서버는 종료했다. 원본 프로젝트의 실행 중 서버와 데이터는 변경하지 않았으며, 소스 반영 후 사용자 터미널에서 재시작해야 적용된다.

## 성능 자료

- `SEARCH_PERFORMANCE.md`: 정확 일치 예비 비교와 최종 부분 포함 비교를 구분한다.
- `ALGORITHM_2_COURSE_RECOMMENDATION.md`: 실제 계산기 실행 시간과 SQL 왕복 수.
- `PASSWORD_STORAGE.md`: 해싱 비용·동시 검증 실험 및 한계.
- `benchmarks/`: 재현 소스와 CSV 원자료.

기존 H2 데이터는 유지한다. 최초 업데이트 실행 시 검색 인덱스를 새로 만들며 기존 회원의 BCrypt는 성공 로그인 때만 Argon2id로 전환한다. 기존 글의 ID를 재배정하거나 `demo-*` 관광지를 실제 관광지와 임의 병합하지 않는다.
