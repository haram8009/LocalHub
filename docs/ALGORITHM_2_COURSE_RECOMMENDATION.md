# 제안 2 — Jaccard + LCS 유사 여행 코스 추천 적용 기획서

## 목적과 서비스

게시글 상세에서 현재 코스와 장소 구성 및 방문 순서가 비슷한 다른 게시글을 추천한다. 회원 취향을 학습하는 개인화 추천이 아니라 현재 보고 있는 코스를 기준으로 한 콘텐츠 추천이다. 사용자는 추천 카드에서 유사도와 ‘공통 관광지 n곳 · 같은 방문 순서 m곳’을 확인하고 다른 코스로 이동한다.

## 구현 및 입력·출력

- 계산: `backend/src/main/java/com/enjoytrip/CourseSimilarityCalculator.java`
- 조회·순위: `CourseRecommendationService.java`, `PostRepository.java`
- API: `GET /api/posts/{postId}/similar?limit=3`, limit 1~10, 누락 글 404, 잘못된 limit 400
- 화면: `frontend/src/views/PostDetailView.vue`
- 입력: 저장된 장소의 `contentId`를 방문 순서로 정렬한 배열 2개
- 출력: `score`, `commonPlaceCount`, `lcsLength`, `placeSimilarity`, `orderSimilarity`와 기존 게시글 표시 필드

현재 서비스의 장소 스냅샷 모델을 활용한다. 같은 TourAPI `contentId`를 같은 장소로 비교하며 장소명·주소·좌표로 관광지를 임의 병합하지 않는다. `demo-*`와 실제 관광지 ID도 별개로 취급한다. 기존 데이터의 중복 장소는 첫 방문만 남겨 비교하고 빈 ID는 제외한다. 기존 샘플들처럼 공통 ID가 없으면 추천 결과가 비어 있는 것이 정상이다. 공통 실제 관광지를 선택한 코스를 등록하면 추천에 반영된다.

## 알고리즘

1. HashSet으로 공통 고유 장소 수와 합집합 크기를 계산한다.
2. 두 행의 DP 배열을 번갈아 사용하여 LCS 길이를 계산한다.
3. 아래 점수를 반올림하지 않은 상태로 정렬한다.

```text
Jaccard = 교집합 크기 / 합집합 크기
순서 유사도 = LCS 길이 / max(두 코스 길이)
score = 0.6 × Jaccard + 0.4 × 순서 유사도
```

`A B C D`와 `A B E D`는 0.66, `D C B A`는 0.70이다. 장소 겹침의 비중이 커 역순 코스가 더 높은 경우도 있다. 같은 점수는 생성일 내림차순, ID 내림차순이다. 화면에서만 백분율을 반올림한다.

기준 글 자신, 빈 코스, 공통 장소가 없는 글을 제외한다. 먼저 공통 장소 후보 ID를 DB에서 찾고 후보들의 장소를 한 번에 가져온다. 후보 전체에 점수를 계산한 뒤 상위 결과의 표시 데이터만 조회한다. 후보 수가 늘어도 SQL 왕복 수는 최대 6회이며 후보마다 장소를 조회하지 않는다. 추천 요청 자체는 조회수를 올리지 않는다.

## 복잡도

두 코스 길이를 M, N이라 할 때 Jaccard는 기대 O(M+N), LCS는 O(MN) 시간과 O(min(M,N)) 공간이다. 후보 P개, 최대 길이 L이면 계산은 O(P×L²), 전체 정렬은 O(P log P)이다. SQL/직렬화 비용은 별도로 고려한다.

## 검증 결과

- 동일·역순·부분 일치·불일치·빈 코스·중복/빈 ID 검증
- 두 행 LCS를 독립적인 부분수열 완전 탐색과 고정 난수 500쌍으로 비교
- 자기 글 제외, 동점 ID 정렬, 수정·삭제 직후 반영, limit와 404 검증
- 후보 20개 테스트에서 추천 SQL 최대 6회 확인
- 상세 화면의 점수/이유, 추천 글 이동, 오류·재시도 테스트
