# FE 로컬 전환 계획: 자체 서버 → 공공데이터 API + localStorage

## Context
`FE/`(Vue 3 + Pinia + Vite)는 LocalHub 자체 서버(`VITE_API_BASE_URL`의 `/api/locations`, `/api/posts`, `/api/chat`)와 통신하도록 작성되어 있다. 서버 없이 동작하도록 바꾼다.
- **여행지**: 한국관광공사 KorService2를 브라우저에서 직접 호출한다. CORS는 확인 완료(`Access-Control-Allow-Origin`이 요청 origin을 그대로 반환).
- **게시글(코스 공유)**: localStorage에 저장하고 읽는다.
- **챗봇**: 제거한다(사용자 결정).

뷰/컴포넌트는 최대한 그대로 두기 위해 **서비스 함수의 시그니처와 반환 형태(normalize 결과)를 유지**하고 내부 구현만 교체하는 것이 원칙이다.

## 현재 구조 요약
| 파일 | 역할 | 사용처 |
|---|---|---|
| `services/api.js` | `apiRequest`(fetch + 로딩 + ApiError) | 모든 서비스 |
| `services/locationService.js` | `getLocations({category,query,bounds,limit,signal,showLoading})`, `getLocation(id)`, `getNearbyLocations(id,{limit})`, `normalizeLocationResponse` | MapView, PostForm, PostCreateView, home |
| `services/posts.js` | `getPosts({query,category,placeId,page,size})`, `getPost`, `createPost`, `updatePost`, `deletePost(id,pw)` | PostList/Detail/Create/Edit, MapView, home |
| `services/locationMapCache.js` | bounds 기반 메모리 캐시 | MapView |
| `services/directions.js` | 카카오모빌리티 길찾기(외부 API, 서버 무관) | CourseKakaoMap |
| `services/chat.js` | `/api/chat` | ChatWidget |
| `stores/ui.js` | 로딩 카운터 | api.js, AppLoading |
| `stores/app.js`, `stores/counter.js` | 미사용 보일러플레이트 | — |

## 변경 계획

### 1. `services/api.js` → 범용 fetch 래퍼로 축소
- `API_BASE_URL`/`buildUrl` 상대경로 처리와 FastAPI용 `detail[]` 파싱을 제거한다.
- `apiRequest(url, options)`는 절대 URL만 받는다. 로딩 처리(`useUiStore`)와 `ApiError`, AbortError 전달은 그대로 둔다(directions.js가 계속 사용).

### 2. 신규 `services/tourApi.js` — 관광공사 API 클라이언트
- Base `https://apis.data.go.kr/B551011/KorService2`
- 공통 파라미터: `serviceKey=VITE_TOUR_API_KEY`(**Decoding 키**를 `URLSearchParams`로 인코딩), `MobileOS=ETC`, `MobileApp=EnjoyTrip`, `_type=json`
- `tourRequest(operation, params, {signal, showLoading})`:
  - `apiRequest` 호출
  - `response.header.resultCode !== '0000'`이면 ApiError로 처리
  - `body.items.item`을 정규화한다. 빈 결과면 `""`, 1건이면 객체로 오므로 항상 배열로 만든다.
  - `totalCount`를 함께 반환한다.
- 카테고리 ↔ contentTypeId 매핑 상수: 관광지 12, 문화시설 14, 축제공연행사 15, 여행코스 25, 레포츠 28, 숙박 32, 쇼핑 38, 음식점 39. MapFilterBar와 PostForm의 한글 라벨을 그대로 키로 쓴다.
- 오퍼레이션 래퍼:
  - `areaBasedSyncList2`, `locationBasedList2`(mapX, mapY, radius ≤ 20000), `searchKeyword2`
  - `detailCommon2`(contentId로 단건 조회 — 개요, 좌표)
  - `detailIntro2`(contentId + contentTypeId 필수 — 화장실·이용시간·주차 등)
  - `detailImage2`, `detailInfo2`

### 3. `services/locationService.js` — 내부만 교체, 시그니처 유지
- `normalizeLocation`을 관광공사 필드 기준으로 정리한다.
  - `contentid → id/contentId`, `title → name`, `contenttypeid → category/categoryLabel`(매핑 역변환), `addr1 + addr2 → address`
  - `mapy → latitude`, `mapx → longitude`, `firstimage2/firstimage → 썸네일/원본`, `dist(m) → distanceKm`
  - 기존 반환 키는 그대로 유지해 컴포넌트가 수정 없이 동작하게 한다.
- `getLocations({category, query, bounds, limit, signal, showLoading})`
  - `query`가 있으면 `searchKeyword2`(keyword, contentTypeId, numOfRows=limit)를 호출한다.
  - `bounds`가 있으면 `locationBasedList2`를 호출한다. 중심 = bounds 중앙, radius = 중심~모서리 거리(m, `utils/geo.js` 재사용, 최대 20000)이다. 응답은 기존 `filterLocationsByBounds`로 사각형 범위에 맞게 자른다.
  - 둘 다 없으면 `areaBasedSyncList2`를 호출한다(PostForm 초기 목록, home 추천).
  - `numOfRows` 상한: API 페이지 크기가 제한적이므로 MapView의 `LOCATION_LIMIT=500`을 100 수준으로 낮춘다(MapView 상수 1줄 수정).
- `getLocation(contentId)`: `detailCommon2` → normalize
- `getNearbyLocations(contentId, {limit})`: 먼저 `getLocation`으로 좌표를 얻는다(이미 location 객체를 받는 오버로드도 허용해 호출 1회를 절약). 이어서 `locationBasedList2`(radius 5000, arrange=E 거리순)를 호출하고, 자기 자신을 제외한 뒤 limit개를 반환한다.
- 신규 `getLocationDetail(location)`: `detailIntro2` + `detailImage2` + `detailInfo2`를 `Promise.allSettled`로 병렬 호출한다. 반환 형태는 `{ intro: {라벨: 값}[], images: string[], infos: [] }`이며, 소개 정보는 타입별 필드를 사람이 읽을 라벨로 매핑한다(예: `restroom/chkcreditcard/parking/usetime/infocenter`).
- 사용자 요청 흐름(지역 목록 → 첫 항목 좌표로 위치기반 조회 → 이후엔 포커스만 이동)은 MapView가 이미 갖추고 있다. 선택 시 `focusLocation`만 바꾸고, 뷰포트 변경 시 bounds로 재조회한다. 서비스만 바꾸면 그대로 성립한다.

### 4. `services/posts.js` → localStorage 저장소
- 신규 `services/storage.js`: `readJson(key, fallback)` / `writeJson(key, value)`를 둔다. JSON 파싱 실패와 접근 예외는 try/catch로 처리한다.
- 키 `enjoytrip:posts`(배열), `enjoytrip:postSeq`(id 시퀀스)
- 저장 레코드:
  - `{id, category, title, content, passwordHash, viewCount, createdAt, updatedAt, locations:[{...normalizedLocation, visitOrder}]}`
  - **서버 조인이 없으므로 위치 스냅샷 전체를 저장**한다. PostForm의 `selectedLocations`가 이미 normalize된 객체라 그대로 쓸 수 있다.
- 함수별 구현(시그니처와 반환 형태 유지 → 뷰 수정 불필요)
  - `getPosts`: 필터는 query(제목·내용 포함), category, placeId(locations에 contentId 포함)이다. createdAt 내림차순으로 정렬하고 page/size로 잘라 `{items,page,size,total,totalPages}`를 반환한다.
  - `getPost`: 조회 시 viewCount를 +1 하고 저장한다. 없으면 `ApiError('요청한 정보를 찾을 수 없습니다.', {status:404})`
  - `createPost` / `updatePost` / `deletePost`: 비밀번호를 `crypto.subtle.digest('SHA-256')` 해시로 비교한다. 불일치하면 기존과 동일하게 status 403 메시지를 낸다(PostDetailView의 에러 표시 로직 재사용).
  - 모든 함수는 `async`로 유지한다(뷰의 await, try/catch 흐름 보존).
- `serializePostPayload`, `normalizePostListResponse`의 snake_case 처리는 정리한다. `normalizePost`는 export되어 있으므로 유지한다.
- (선택) 첫 실행 시 데모용 시드 게시글 1~2개 → 홈 "최근 코스"가 비지 않게 한다.

### 5. `services/locationMapCache.js`
- 로직은 그대로 재사용한다(메모리 캐시, bounds 포함 판정). 공공 API 일일 호출 한도 절약에 유효하다.
- 변경 사항은 없다.

### 6. 챗봇 제거
- 삭제: `components/chat/ChatWidget.vue`, `components/common/ChatWidget.vue`, `services/chat.js`, `services/__tests__/chat.spec.js`
- 수정: `layouts/AppLayout.vue`(import·태그 제거), `components/common/index.js`(export 제거)
- `docs/API설계.md`의 챗 섹션을 제거한다.

### 7. stores
- `stores/ui.js`는 유지한다(로딩 카운터, 변경 없음).
- 미사용 `stores/counter.js`, `stores/app.js`는 삭제한다. 삭제 전에 참조가 없는지 grep으로 확인한다.
- 게시글을 Pinia 스토어로 옮기지 않는다. 뷰들이 서비스 함수를 직접 호출하는 구조이므로, **localStorage 접근은 `services/posts.js` 한 곳에 캡슐화**하는 편이 변경 범위가 가장 작다. (Pinia persist 플러그인 같은 의존성 추가도 불필요하다.)

### 8. 상세 패널에 공공데이터 상세 연결 (요구사항: 화장실·이미지 등)
- `MapView.loadLocationContext`의 `Promise.all`에 `getLocationDetail(location)`을 추가하고 `locationDetail` ref를 `MapSidePanel` → `LocationDetailPanel`로 전달한다.
- 패널에는 "이용 정보" 목록과 이미지 갤러리 섹션만 추가한다(기존 스타일 클래스 재사용).

### 9. 환경변수·설정
- `.env.example` 추가: `VITE_TOUR_API_KEY=`, `VITE_KAKAO_MAP_APP_KEY=`(기존 사용 키 확인 후 표기), `VITE_KAKAO_REST_API_KEY=`
- `VITE_API_BASE_URL` 사용처를 제거하고, `netlify.toml`의 `SECRETS_SCAN_OMIT_KEYS`를 `VITE_TOUR_API_KEY` 등으로 교체한다.
- `.gitignore`는 이미 `.env`를 제외하고 있다.

### 10. 테스트 갱신 (`services/__tests__`)
- `locations.spec.js`: `apiRequest` mock은 유지하고, 기대 URL을 관광공사 오퍼레이션/파라미터로 바꾼다. 응답 픽스처는 `{response:{header:{resultCode:'0000'},body:{items:{item:[...]}}}}` 형태로 하고, 단건 객체와 빈 문자열 케이스를 추가한다.
- `posts.spec.js`: `apiRequest` mock을 제거한다. jsdom localStorage를 쓰며, `beforeEach`에서 `localStorage.clear()`를 호출한다. 다음을 검증한다.
  - CRUD
  - 비밀번호 불일치 시 403
  - placeId 필터
  - 페이지네이션
- `locationMapCache.spec.js`, `directions.spec.js`: 변경 없음
- 컴포넌트 테스트(`KakaoTravelMap.spec`, `LocationListPanel.spec`)는 normalize 형태가 유지되므로 통과해야 한다.

## 작업 순서
1. `storage.js`, `tourApi.js` 추가 → 2. `api.js` 정리 → 3. `locationService.js` 교체 → 4. `posts.js` 교체 → 5. 챗봇·미사용 스토어 제거 → 6. MapView/상세 패널 연결 → 7. 테스트·문서·env 정리

이 계획 문서는 승인 후 `FE/docs/로컬전환계획.md`로도 저장해 팀 공유용으로 남긴다.

## 검증
- `npm run test:unit -- --run`: 서비스와 컴포넌트 테스트 전체 통과
- `npm run lint`
- `npm run dev` 후 내장 브라우저에서 확인:
  - `/map` 진입 시 마커와 목록이 로드되고, 카테고리 칩과 키워드 검색이 동작하는지
  - 목록 클릭 시 포커스만 이동하는지(네트워크 탭에서 목록 재요청이 없는지)
  - 상세 패널에 화장실·이용시간·이미지가 표시되는지
  - 코스 작성 → 목록 → 상세 → 수정 → 삭제가 되고, 새로고침 후에도 유지되는지(localStorage)
  - 틀린 비밀번호 입력 시 에러가 표시되는지
  - 콘솔에 `/api/` 요청이나 CORS 에러가 없는지
